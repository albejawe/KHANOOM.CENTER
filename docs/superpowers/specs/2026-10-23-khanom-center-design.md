# مواصفات مشروع khanom-center (مجمع خانم)

**التاريخ:** 2026-10-23
**الحالة:** بانتظار مراجعة صاحب المشروع

## 1. الهدف
موقع **عرض فقط** لمنتجات مجمع خانم (ملابس نسائية، ملابس أطفال، كوزمتكس). صاحب المجمع يرسل الرابط للزبائن ليتصفحوا المنتجات.
الجمهور قليل الخبرة بالمواقع، لذلك الأولوية المطلقة: **البساطة والسرعة**. التصفح يكون مثل تطبيقات التواصل الاجتماعي، صور كبيرة وضغطات قليلة.

**خارج النطاق:** الطلب، السلة، الدفع، حسابات الزوار، البحث، أعداد المخزون.

## 2. التقنيات
| الجزء | التقنية |
|---|---|
| الإطار | Next.js (App Router) + TypeScript + Tailwind CSS |
| الاستضافة | Vercel (`khanom-center.vercel.app`)، ينشر تلقائياً من GitHub |
| قاعدة البيانات | Turso (libSQL) |
| الصور | Cloudflare R2، تُعرض للزائر مباشرة عبر رابط `r2.dev` العام |
| المستودع | `github.com/albejawe/khanom-center` |

- الصور **لا تمر عبر Vercel أبداً**: تُرفع مباشرة من المتصفح إلى R2 عبر روابط موقّعة (presigned PUT)، وتُعرض مباشرة من R2.
- لا نستخدم `next/image` optimization، حتى لا نستهلك حدود Vercel. الصور مضغوطة مسبقاً.
- رابط الصور يأتي من متغير بيئة `NEXT_PUBLIC_IMAGE_BASE_URL`، فالتحويل لاحقاً لدومين خاص لا يحتاج تغيير الكود.

## 3. نموذج البيانات (Turso)
```sql
categories (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id INTEGER NULL REFERENCES categories(id) ON DELETE RESTRICT, -- NULL = قسم رئيسي
  image_key TEXT NULL,          -- صورة غلاف القسم
  sort_order INTEGER NOT NULL DEFAULT 0
)
sizes (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  sort_order INTEGER NOT NULL DEFAULT 0
)
products (
  id INTEGER PRIMARY KEY,
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE RESTRICT, -- فئة فرعية دائماً
  price INTEGER NOT NULL,       -- بالدينار العراقي
  description TEXT NULL,
  image_key TEXT NOT NULL,      -- مثال: products/<uuid>
  is_hidden INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
)
product_sizes (
  product_id INTEGER NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  size_id INTEGER NOT NULL REFERENCES sizes(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, size_id)
)
```
- **مستويان فقط:** قسم رئيسي ← فئة فرعية. المنتج يرتبط دائماً بفئة فرعية.
- **كل منتج = صورة واحدة.** كل صورة تُحفظ بنسختين في R2: `<key>-thumb.webp` (عرض ~400px، حوالي 30KB) و `<key>-full.webp` (عرض ~1280px، حوالي 150KB).
- لا يمكن حذف قسم فيه فئات أو منتجات، وتظهر رسالة واضحة.

## 4. واجهة الزائر
| الرابط | المحتوى |
|---|---|
| `/` | شعار "مجمع خانم" + شبكة بعمودين من بطاقات كبيرة بالصور للأقسام الرئيسية |
| `/c/[id]` | الفئات الفرعية للقسم بنفس شكل البطاقات + زر رجوع |
| `/s/[id]` | شبكة صور 3 أعمدة (مثل بروفايل إنستغرام) لمنتجات الفئة، الأحدث أولاً |
| `/s/[id]?p=[productId]` | عارض بكامل الشاشة فوق الشبكة |

**العارض:** صورة كبيرة، سحب يمين ويسار للتنقل بين منتجات نفس الفئة، تكبير بالأصابع، وتحت الصورة السعر (`25,000 د.ع`) والقياسات المتوفرة والوصف إن وجد.
المنتج المفتوح ينحفظ بالرابط، فـ**زر الرجوع بالموبايل يغلق العارض** بدل ما يطلع من الموقع، وأي منتج يمكن مشاركة رابطه.

**قواعد العرض:**
- الأقسام والفئات الفارغة (بدون منتجات ظاهرة) لا تظهر للزائر.
- المنتجات المخفية (`is_hidden`) لا تظهر.
- عربي RTL، الموبايل أولاً، خط عربي واضح، أزرار ومناطق ضغط كبيرة (48px كحد أدنى)، نصوص قليلة.
- الصور تحمّل تدريجياً (`loading="lazy"`) بأبعاد ثابتة حتى لا تقفز الصفحة.

**السرعة:** الصفحات العامة مولّدة مسبقاً ومخزنة (ISR). عند أي تعديل من لوحة التحكم تُحدَّث الصفحات فوراً (`revalidatePath`). لذلك الزائر لا يستعلم من قاعدة البيانات مباشرة.

## 5. لوحة التحكم (`/admin`)
**الدخول:** صفحة `/admin/login` بيوزر وباسوورد يُقارنان على الخادم مع متغيري البيئة `ADMIN_USERNAME` و `ADMIN_PASSWORD`. عند النجاح يُحفظ cookie موقّع (httpOnly، صالح 30 يوماً، موقّع بـ `AUTH_SECRET`). الـ middleware يحمي كل `/admin/*` وكل الأوامر الإدارية. الباسوورد لا يُكتب في الكود.

**التنقل:** شريط سفلي بثلاث تبويبات: **المنتجات | الأقسام | القياسات**.

**المنتجات:**
- شبكة بكل المنتجات مع فلتر حسب القسم والفئة، وكل منتج تظهر عليه علامة إذا كان مخفياً.
- زر كبير **"+ إضافة منتجات"**:
  1. اختيار صورة أو عدة صور من الاستوديو.
  2. تحديد القسم الرئيسي ← الفئة الفرعية، والقياسات (من القائمة الجاهزة)، والسعر، والوصف (اختياري)، **مرة واحدة للكل**.
  3. حفظ: كل صورة تصبح منتجاً مستقلاً بنفس المعلومات.
- الضغط على منتج يفتح التعديل: تغيير الفئة والقياسات والسعر والوصف والصورة، وإخفاء أو إظهار، وحذف (مع تأكيد).

**الأقسام:** إضافة وتعديل وحذف الأقسام الرئيسية والفئات الفرعية (اسم + صورة غلاف + ترتيب).

**القياسات:** إضافة وتعديل وحذف القياسات (مثل S، M، L، XL، 2-3 سنوات...) مع ترتيبها.

## 6. مسار رفع الصور
1. المتصفح يضغط كل صورة (Canvas ← WebP) إلى نسختين: thumb و full.
2. يطلب من الخادم (بعد التحقق من الدخول) روابط PUT موقّعة إلى R2، صالحة لدقائق.
3. يرفع مباشرة إلى R2، **3 صور بالتوازي**، مع شريط تقدم (مثلاً "تم 7 من 20").
4. بعد اكتمال الرفع تُضاف المنتجات لقاعدة البيانات دفعة واحدة (transaction)، ثم تُحدَّث الصفحات.
5. الصور الفاشلة تظهر بقائمة مع زر **"إعادة المحاولة"**، والناجحة لا تُعاد.
6. حذف منتج يحذف صورتيه من R2.

## 7. متغيرات البيئة
```
TURSO_DATABASE_URL, TURSO_AUTH_TOKEN
R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET
NEXT_PUBLIC_IMAGE_BASE_URL   # https://pub-xxxx.r2.dev
ADMIN_USERNAME, ADMIN_PASSWORD, AUTH_SECRET
```
محلياً تُحفظ في `.env.local` (مستثنى من Git)، وعلى Vercel يضيفها صاحب المشروع من الإعدادات.

## 8. الأخطاء والاختبار
- كل عملية في اللوحة تظهر نتيجتها برسالة عربية واضحة (نجاح أو خطأ).
- عند تعذر الاتصال بقاعدة البيانات تبقى الصفحات العامة المخزنة تعمل.
- اختبارات وحدة (Vitest) للدوال البحتة: تنسيق السعر، اشتقاق مفاتيح الصور، توقيع والتحقق من cookie الدخول، التحقق من بيانات النماذج.
- قبل كل تسليم: `npm run build` ناجح + تجربة يدوية على الموبايل (الرئيسية ← فئة ← شبكة ← عارض، والرفع الجماعي).

## 9. الحدود المتوقعة (مجاناً)
تقريباً **1,000 زائر يومياً**، كل واحد يشاهد ~300 صورة (حد R2: عشرة ملايين قراءة شهرياً). بعدها تكلفة بسيطة جداً، أو تحويل لدومين خاص بتغيير متغير واحد.
